# 셀 케어 알림함·코멘트 답글

## 구현 범위

- 상단 종 아이콘에서 최근 알림 100개, 내용 미리보기, 개별 읽음/모두 읽음을 확인한다. 화면이 보이는 동안 60초 간격 및 다시 돌아올 때 갱신한다.
- 보고서·코멘트·메시지·성도 동정·공지는 해당 항목으로 이동한다. 로그인 전 열었던 알림 목적지도 로그인 요청에 보존한다. 작성 중인 보고 저장에 실패하면 이동을 중단한다.
- 기존 공개/비공개 코멘트를 볼 수 있는 활성 사용자만 답글을 읽고 쓴다. 일반 보고 코멘트와 수신인별 비공개 코멘트의 권한을 섞지 않는다. 본인 답글만 삭제할 수 있다.
- 답글 수신자는 원 코멘트 작성자다. 답글은 즉시 알림함에 기록하고, 기기 구독이 있으면 푸시도 시도한다. 현재 답글은 원문으로 표시하며 자동 번역은 추가하지 않았다.
- 한국어 화면·도움말·서버 알림의 호칭은 담임 목사님·담임 사모님으로 정리한다. 계정 이름과 역할 데이터는 변경하지 않는다.

## DB 및 권한

새 객체는 모두 `report` 스키마의 `cellcare_` 접두어를 사용한다. `public`/`auth` 객체나 기존 트리거·행은 변경하지 않는다. 셀 케어의 기존 사용자·대상 자료는 읽기만 한다. 사역 보고 앱의 프로필/소속과 혼합하지 않는다.

- `report.cellcare_notification_items`: 수신자별 알림과 읽음 상태.
- `report.cellcare_comment_replies`: 보고/동정 코멘트의 답글.
- 두 테이블 모두 RLS를 켜고 일반 클라이언트의 직접 접근·TRUNCATE를 허용하지 않는다. 인증된 RPC가 기존 셀 케어 권한과 현재 활성 상태를 검사한다.
- 알림 목록과 이동 시 원본의 현재 열람 권한을 재검사한다. 삭제·권한 회수된 항목은 숨긴다. 기능 관리자라는 이유만으로 자료 접근을 추가하지 않는다.
- 기기 구독과 무관하게 최근 30일의 허용된 업무 이벤트를 알림 조회 시 중복 없이 기록한다. 그 이전 푸시 전송 이력은 복원하지 않는다. 크론/테스트 알림은 새 발송 시 기록한다.
- 기존 푸시 대상 계산은 그대로 사용한다. 서버의 새 `cellcare_` RPC는 `Content-Profile: report`, 브라우저는 `sb.schema('report')`로 접근한다.

## 운영 반영 순서

1. 사용자에게 새 저장 구조와 권한 범위를 설명하고 운영 DB 적용·배포 승인을 받는다.
2. 기존 객체·원본 행 보존을 확인하면서 `supabase/migrations/20261021010000_notifications_replies.sql` **한 파일만** 적용한다. 다른 임시 작업의 마이그레이션은 포함하지 않는다.
3. 함수 EXECUTE 권한, 테이블 RLS/직접 접근 거부, public/auth 원본 보존을 검사한다.
4. 앱·서버·서비스 워커를 함께 배포한다. DB보다 앱을 먼저 배포하면 새 RPC를 찾지 못한다.
5. 실제 계정별로 종 아이콘, 알림 열기, 읽음 처리, 보고/비공개/성도 동정 답글 권한을 확인한다. 실제 푸시/답글 생성 검증은 운영 데이터 생성·알림 전송을 별도로 고려해 진행한다.

로컬 검증은 `npm test`로 실행한다. DB 테스트는 PGlite의 격리된 가상 자료를 사용하며 운영에 접속하지 않는다. `@electric-sql/pglite`는 개발 의존성이다.
